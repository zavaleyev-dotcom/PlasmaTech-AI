# `src/materials` — реестр материалов (Stage 6 / M1.3.1–M1.3.2)

Описывает, **чем является материал** (M1.3.1: идентичность, состав, фаза, структура, форма, многослойные системы) и **как хранится скалярное значение свойства** конкретного варианта (M1.3.2: определения свойств, условия, происхождение, неопределённость, версия записи). **Значений свойств реальных материалов здесь нет**: только схема и валидаторы; записи существуют лишь как синтетические фикстуры в тестах. Нет интерфейса, экспорта, запросов, выбора значений, интерполяции и моделей (M1.3.3–M1.3.4).

Зависимости: `@/physics` (величины длины, температуры, безразмерные; точная арифметика долей), чистая функция нормализации DOI.

## Модель
| Сущность | Что это |
|---|---|
| `MaterialIdentity` | `id` (`ref:` / `user:` / `fixture:` + слаг), вид `MaterialKind`, название (рус. обязательно), синонимы, обозначения (только с источником) |
| `MaterialKind` | `element`, `compound`, `alloy`, `ceramic`, `composite`, `coating_system` |
| `MaterialComposition` | `element`; `alloy` (доли элементов); `stoichiometric` (количества на формульную единицу); `composite` (доли вариантов-компонент); `coating_system` (стек) |
| `MaterialPhase` | агрегатное состояние + кристаллический порядок + (для кристаллов) кристаллическая структура + область стабильности |
| `MaterialStructure` | микроструктура твёрдого тела: размер зерна, текстура, пористость, признаки |
| `MaterialForm` | `bulk`, `thin_film`, `coating_layer`, `sputtering_target`, `powder`, `foil`, `substrate`; контекст плёнки — технология и подложка; назначение — только метка |
| `MaterialVariant` | идентичность + состав + фаза + структура + форма. **Свойство в будущем принадлежит варианту, а не названию материала** |
| `MaterialLayer`, `MaterialStack` | слои (однородный или градиентный), повторяющиеся пакеты, границы между слоями |

## Принятые решения (ограничения реализации)
1. Реестр находится в `src/materials/`, отдельно от физического ядра.
2. **Агрегатное состояние и микроструктура — разные сущности.** Кристаллический порядок задаётся явно: `crystalline`, `partially_crystalline`, `amorphous`, `unknown` (твёрдое тело) или `not_applicable` (жидкость, газ, плазма). `unknown` ≠ кристалличность и ≠ аморфность: отсутствие сведений ничего не доказывает. Кристаллическая структура — только при кристаллическом порядке; размер зерна и текстура — не для аморфного и не для нетвёрдого.
3. **Массивный материал, мишень и тонкая плёнка — разные варианты** и автоматически не эквивалентны. Технология получения плёнки и подложка — контекст варианта; назначение (`intendedUse`) — метка, которая ничего не определяет.
4. Неизвестная неопределённость не равна нулевой (вводится в M1.3.2; здесь значений с неопределённостью нет).
5. Номинальный расчёт возможен без неопределённости, но оценка неопределённости результата требует достаточных данных (M1.3.2+).
6. Литературные значения с разными условиями автоматически не считаются противоречивыми (M1.3.3).
7. Автоматического усреднения значений нет и не будет.
8. **Многослойные системы:** последовательность слоёв от подложки, адгезионный/промежуточный/функциональный/защитный/буферный/покрывающий слои, градиентные слои, **повторяющиеся пакеты** (`period`, вложенные до 8 уровней, раскрытие не более 10000 слоёв), границы между слоями. Эффективные свойства стека **не вычисляются** (нужна проверенная физическая модель); из производных — только геометрия: плоский порядок слоёв и суммарная толщина (точная сумма, при отсутствии толщины любого слоя — ошибка).
9. Экстраполяция свойств запрещена (M1.3.4).
10. Данные пользователя (`user:`), поставляемые справочные (`ref:`) и тестовые синтетические (`fixture:`) разделены пространствами имён.

## Состав и доли
- Доли одной композиции имеют **одну базу**: сплав — `mass` или `atomic`; композит — `volume`, `mass` или `molar`. Базы не смешиваются и **не пересчитываются**: массовые ↔ атомные доли требуют проверенных атомных масс, которых в пакете нет, поэтому такого преобразования нет.
- Доли сравниваются точными десятичными числами: 0,1 + 0,2 + 0,7 — ровно 1. Допуск суммы (`sumTolerance`, до 0,01) задаётся явно и даёт предупреждение; по умолчанию сумма точна.
- Доля: `{ value }`, диапазон `{ min, max }` допустимого состава или `{ balance: true }` (остаток; не более одного). Для диапазонов проверяется, что состав с суммой 1 вообще возможен.
- Стехиометрия: `stoichiometric` — целые положительные количества; `nonstoichiometric` — дробные количества или диапазоны (хотя бы одно не целое). Количество — не доля. Атомные доли соединения `count / Σcount` вычисляются без атомных масс (`atomicFractionsFromStoichiometry`), для диапазонов — не определены.
- Символы элементов — закрытый список из 118 (проверен по листингу NIST «Atomic Weights and Isotopic Compositions»); атомных масс и номеров в пакете нет.

## Идентификаторы
Детерминированы: нет `Date.now()` и `Math.random()`. Идентификатор — `<namespace>:<slug>`, слаг задаёт автор записи, пакет его только проверяет; идентификатор элемента выводится из символа (`ref:element-ti`). `contentFingerprint` (FNV-1a 64 от канонического JSON) нужен для обнаружения дубликатов и не является идентификатором. CAS, UNS, ГОСТ и другие обозначения **никогда не присваиваются автоматически**: только вручную, с источником (`designation_unsourced` иначе).

## Валидация
Валидаторы не бросают исключений на плохих данных, а собирают замечания `{ code, severity, path, message }` (`error` / `warning` / `info`); `create*` бросают `MaterialsError` со всеми замечаниями, если есть ошибки, и возвращают глубоко замороженную копию. Неизвестные поля — ошибка (подсунутое свойство не игнорируется молча). Отсутствие данных не заполняется: `describeMissingData` перечисляет, чего вариант не сообщает. Каталог (`validateCatalog`): уникальность идентификаторов, разрешение ссылок, соответствие вида композиции виду идентичности, **запрет циклических ссылок** (композит в самом себе, плёнка на собственной подложке), слои — материалы, а не вложенные системы покрытий; одинаковое содержимое под разными идентификаторами — предупреждение, записи не объединяются.

Коды замечаний: `invalid_id`, `duplicate_id`, `invalid_kind`, `invalid_name`, `invalid_designation`, `designation_unsourced`, `invalid_source`, `invalid_symbol`, `duplicate_symbol`, `kind_composition_mismatch`, `invalid_composition`, `fraction_malformed`, `fraction_out_of_range`, `fraction_sum`, `fraction_range_infeasible`, `balance_invalid`, `too_few_constituents`, `invalid_tolerance`, `stoichiometry_invalid`, `too_few_species`, `invalid_phase`, `state_order_mismatch`, `crystal_structure_not_applicable`, `phase_not_applicable`, `phase_required`, `invalid_structure`, `structure_not_applicable`, `invalid_quantity`, `invalid_form`, `form_field_not_allowed`, `form_kind_mismatch`, `state_form_mismatch`, `state_form_ambiguous`, `substrate_conflict`, `invalid_stack`, `duplicate_layer_id`, `invalid_layer`, `invalid_period`, `invalid_interface`, `stack_too_large`, `missing_reference`, `reference_cycle`, `nested_coating_system`, `missing_data`, `invalid_material`, `sum_not_exact`, `order_unknown`.

## Правила, добавленные по результатам аудита
- **Остаток (`balance`).** Отрицательный остаток невозможен физически: сумма минимальных значений остальных компонент не должна превышать 1, **допуск суммы на остаток не распространяется** (допуск оправдывает округление опубликованной суммы, но не отрицательную долю). Для диапазонов достаточно, чтобы существовал состав с неотрицательным остатком.
- **Валидатор не бросает исключений на повреждённых данных:** любой доступ к записи предваряется структурной проверкой (`null`, отсутствующие и некорректные поля дают замечания `ValidationReport`), в том числе в каталоге.
- **Ссылки хранят роль** (`variantReferences`: `constituent`, `stack_substrate`, `form_substrate`, `layer_material`, `gradient_from`, `gradient_to`), роль не выводится по совпадению идентификаторов. Система покрытий **не может быть материалом слоя или концом градиентного слоя** (`nested_coating_system`), но может быть подложкой. Циклы ищутся по ссылкам всех ролей.
- **Состояние и форма проверяются совместно** (таблица `STATE_FORM_COMPATIBILITY`): твёрдое тело — любая форма; жидкость — объём (bulk) допустим, плёнка, слой, мишень и подложка возможны, но требуют пояснения контекста (`state_form_ambiguous`, предупреждение), порошок и фольга несовместимы; газ и плазма — только объём, прочие формы — ошибка `state_form_mismatch`.
- **Неизвестные поля** — ошибка схемы на всех уровнях: величина (`{ value, unit }`), источник (`{ citation, doi, locator }`), каталог (`{ identities, variants }`), состав, фаза, структура, форма, слой, граница. Поля не удаляются молча и не сохраняются как прошедшие проверку.
- **Единый источник геометрии стека.** У системы покрытий нет собственной толщины в `form` (`form_field_not_allowed`): толщина выводится только из стека (`totalThickness`); отдельная измеренная толщина потребует собственной семантики и происхождения (отдельный этап). Подложка: если она задана и в `form.substrate`, и в `stack.substrate`, значения должны совпадать (`substrate_conflict`).

## Свойства (M1.3.2)

### Определения (`PROPERTY_DEFINITIONS`)
Только определения, без чисел. Каждое свойство выражено в роде физического ядра (`src/physics/` не менялся, похожие рода не подставлялись): плотность (`massDensity`), теплопроводность, удельная теплоёмкость, КЛТР (`linearExpansionCoefficient`), удельное сопротивление, проводимость, молярная масса, модуль Юнга, модуль сдвига, объёмный модуль (три отдельных свойства одного рода `elasticModulus`), температуропроводность. У определения: id, русское и английское название, род, каноническая единица СИ и размерность (берутся из рода), определение, допустимые формы значения (сейчас только `scalar`; `tensor2` и `function` зарезервированы и отклоняются как `unsupported_value_form`), обязательные и допустимые условия.

### Запись (`PropertyRecord`)
`id` (`ref:` / `user:` / `fixture:`), `variant` (id варианта), `property`, `value` (`{ type: 'scalar', value, unit }`), `uncertainty` (всегда присутствует; отсутствие — `{ kind: 'unknown' }`), `conditions`, `provenance`, `version` (целое ≥ 1), `updatedAt`, `supersedes`. Значение принадлежит **варианту**: массивный материал, мишень и плёнка — разные варианты с разными записями, откатов «плёнка → массив» нет. Единица проверяется по роду свойства, значение — на конечность и физические пределы рода.

### Условия (`PropertyConditions`)
Абсолютная температура (точка **или** диапазон), абсолютное давление, атмосфера, направление (`in_plane` / `cross_plane`), опорная температура, определение КЛТР, режим теплоёмкости, метод измерения, состояние материала, толщина плёнки, прочий контекст. Температура — только абсолютная (интервал `K_delta` отклоняется проверкой рода), давление — только абсолютное. Обязательные условия задаёт определение свойства; условие, не относящееся к свойству, — ошибка (`condition_not_allowed`), а не молчаливое сохранение. Свойство не считается применимым вне заявленных условий: значений по умолчанию и «типичных» условий нет.
- **КЛТР:** касательный (`tangent`, производная при температуре T) и средний (`mean`, усреднение между опорной температурой T₀ и T) — разные числа; определение обязательно, для среднего обязательна опорная температура, отличная от T, для касательного она запрещена.
- **Теплоёмкость:** режим `isobaric` / `isochoric` обязателен.
- **Тонкая плёнка / слой покрытия** (если передан вариант): для теплопроводности, удельного сопротивления, проводимости и температуропроводности обязательны толщина и направление; значение плёнки не равно значению массивного материала. Без переданного варианта это не проверяется и не предполагается выполненным.
- Состояние материала в условиях должно совпадать с фазой варианта (`condition_state_mismatch`); температура вне области стабильности фазы — предупреждение.

### Происхождение (`PropertyProvenance`)
Статус значения: `measured`, `evaluated`, `model_estimate`, `user_input`. Источник: тип (`journal_article`, `book`, `handbook`, `standard`, `thesis`, `report`, `database`, `dataset`, `user_data`, `other`), авторы, название, год, идентификаторы (DOI, ISBN, номер стандарта, URL), место в источнике (страница, таблица, рисунок, уравнение, раздел), метод. Для `measured` и `evaluated` обязательны название, год и находимость источника (авторы или идентификатор); для `measured` и `model_estimate` — метод. **Корректный формат DOI — это не проверка существования публикации** (ISBN-10 и ISBN-13 проверяются по длине, контрольной цифре и, для ISBN-13, префиксу 978 или 979 — произвольный EAN-13 не ISBN; URL — по синтаксису; группа регистрации ISBN не проверяется): каждый такой идентификатор сопровождается замечанием `identifier_unchecked`. **Сверка с первоисточником** — отдельное утверждение: `verified_against_source` требует имени сверившего и даты, `unverified` — состояние по умолчанию (замечание `unverified_value`), `not_applicable` — только для данных пользователя. Ничего не выводится из формата идентификатора. Данные пользователя (`user:`) и справочные (`ref:`) разделены: справочная запись не может быть `user_input` и не может ссылаться на вариант другого пространства.

### Неопределённость (`PropertyUncertainty`)
| Вид | Смысл | В `Measured` |
|---|---|---|
| `unknown` | ничего не заявлено; **не равно нулю** | отказ |
| `standard` | стандартная неопределённость u (k = 1) | да, `u` |
| `expanded` | U = k·u; k и его происхождение сохраняются | да, `u = U / k` (точно), **только при известном k** |
| `bounds` | границы значения, не стандартное отклонение | отказ (распределение не предполагается) |

Нулевая неопределённость означает «точно» (как в `Measured`), поэтому допустима только с происхождением `exact_by_definition`; ненулевая с этим происхождением — ошибка. Происхождение оценки (`stated_in_source`, `user_estimate`, `model_output`, `exact_by_definition`) обязательно: вымышленных оценок нет. Номинальное значение можно использовать без известной неопределённости (`propertyNominal`), но результат всегда помечен `metrologicallyConfirmed: false` и перечнем оговорок.

### Граница проверки варианта
Запись проверяется относительно варианта только если он **сам структурно корректен** по правилам M1.3.1 (тот же валидатор `collectVariant`): объекта со строковым `id` недостаточно. Повреждённый вариант (нет `form`, `form: null`, неизвестный вид формы, повреждённые вложенные поля) даёт ошибки варианта и `invalid_material` у записи, а не «проверка пройдена»; повреждённая форма никогда не читается как «массивный материал», условия плёнки не пропускаются. `validatePropertyRecords` проверяет вариант, на который ссылаются записи (не весь каталог — для него `validateCatalog`); идентификатор варианта, встречающийся в каталоге несколько раз, неоднозначен и отклоняется (`duplicate_id`), ни один из вариантов не выбирается. Вариант `null` / `undefined` в `validatePropertyRecord` означает «вариант не передан» (тогда условия плёнки не проверяются и не предполагаются выполненными).

### Что не делается
Нет выбора записи, усреднения, сравнения конфликтующих записей (они хранятся рядом без вердикта), запросов по условиям, интерполяции и экстраполяции — это M1.3.3–M1.3.4. Тензорные свойства и температурные функции не реализованы (формы зарезервированы). Тип `Reference` из `src/services/workspace/references.ts` не используется: он не различает справочник, стандарт и базу данных и получает недетерминированные идентификаторы; переиспользованы лишь нормализация DOI и проверка URL.

Дополнительные коды замечаний M1.3.2: `unknown_property`, `invalid_property`, `invalid_value`, `unsupported_value_form`, `invalid_version`, `namespace_mismatch`, `duplicate_record`, `supersedes_invalid`, `invalid_condition`, `missing_condition`, `condition_not_allowed`, `condition_state_mismatch`, `condition_outside_phase_range`, `invalid_provenance`, `source_unidentifiable`, `missing_locator`, `missing_method`, `invalid_identifier`, `identifier_unchecked`, `verification_inconsistent`, `unverified_value`, `invalid_uncertainty`, `zero_uncertainty`, `expanded_without_k`, `uncertainty_not_convertible`.

## Известные ограничения
- Нет реестра запросов, температурных зависимостей и тензорных свойств (M1.3.3–M1.3.4).
- Твёрдые растворы и подрешётки (например, (Ti,Al)N) описываются только дробными количествами нестехиометрического соединения.
- Словарь признаков микроструктуры, текстуры, технологий — свободный текст; контролируемые словари добавляются по мере появления источников.
- Состав не проверяется на химическую осмысленность (степени окисления и т. п.): пакет проверяет структуру записи, а не истинность данных.
- Тестовые материалы — **синтетические фикстуры** (`fixture:`, «СИНТЕТИЧЕСКИЙ») в `tests/materials-fixtures.ts`; они не являются справочными данными.
